## Agent Brief

**Category:** bug
**Summary:** Compartment rows in tree and General Diagrams wrap at the node's normal width, the way `doc` text already does, and don't stretch the node.

**Current behavior:**
`doc` text in a compartment is wrapped. Other rows (constraint expressions, attribute rows with long values or computed values) are drawn on one line, and the node grows as wide as the longest row.

**Desired behavior:**
Every compartment row wraps at the same width `doc` text uses. Expressions break preferably after an operator or at a space, never inside a name or a unit (`['°C']`). Continuation lines are indented so a wrapped row reads as one row. A single token longer than the width is not broken, and only then may the node grow. The same wrapping appears in the SVG Export and in the GUI.

**Key interfaces:**
- The notation code that builds compartment rows and already wraps `doc` text.
- Node sizing for tree and General Diagrams, which should measure wrapped rows.
- Golden SVGs that have long rows, which will change.

**Acceptance criteria:**
- [ ] A test: a requirement whose constraint is longer than the wrap width is drawn at the normal node width, its constraint on several lines.
- [ ] A test: a long attribute row with a computed value (`mass = a.mass + b.mass + … = 1363.0`) wraps the same way.
- [ ] No line breaks inside an identifier or a unit.
- [ ] bike-radar-model `systemRequirements` (commit `b6a3056`): S11 is as wide as its neighbours.
- [ ] Rows that already fit are unchanged.

**Out of scope:**
- Port labels and wire labels in Interconnection Diagrams: [04](04-layouts-hard-to-read.md), [07](07-interconnection-wires-overlap.md).
- Truncating or eliding text.
