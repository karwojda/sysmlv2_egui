## Agent Brief

**Category:** bug
**Summary:** A tree or General Diagram should draw an element's children in the order the Model declares them.

**Current behavior:**
The Model keeps its elements keyed by qualified name, so declaration order is lost at load and children come out alphabetically. The layered layout then reorders siblings further, presumably to reduce crossings, so the drawn order is neither the Model's nor alphabetical. For requirements written S1…S11, the reader sees a shuffled list.

**Desired behavior:**
Siblings under one parent are drawn left to right in the order they are declared in the Model. Members declared in one file are ordered by their position in it. Where an element's members are spread over files, they are ordered by file path and then position. Elements without a source location come after those with one, by name.

The layout may still reorder to avoid edge crossings *between different parents' subtrees*, but never the children of one parent. A user's Layout (moved nodes) overrides this as it does today.

The Browser keeps whatever order it uses today unless switching it is trivial and consistent. Say which way it went in the PR.

**Key interfaces:**
- `Model` / `Element`: elements carry `source: Option<SourceLocation>` (file and line). A declaration order (line alone isn't enough when two members share a line) may need to be recorded at load, by the OpenSysML backend, from the order the service lists members.
- The layered layout used by tree and General Diagrams, and how it orders siblings.

**Acceptance criteria:**
- [ ] A test: a composite requirement with children declared `c, a, b` draws them `c, a, b` left to right.
- [ ] A test: a part definition with parts declared in non-alphabetical order draws them in declaration order in a General Diagram.
- [ ] Two members declared on one line keep their order.
- [ ] bike-radar-model `systemRequirements` (commit `b6a3056`) draws S1 to S11 in order.
- [ ] Diagrams with a saved Layout are unchanged for the nodes the Layout positions.

**Out of scope:**
- Wrapping wide rows and edge fan-in: [10](10-wide-trees.md).
- Sorting by short name / ID (`<'S1'>`). Model order is what the author chose.
- Interconnection Diagram child placement.
