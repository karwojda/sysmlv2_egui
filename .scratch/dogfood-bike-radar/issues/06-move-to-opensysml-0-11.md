# 06: Move to OpenSysML 0.11

**Status:** ready-for-agent

**Category:** enhancement

**Slice:** bike-radar-model slice 1 (commit `59df5e2`). Split out of [03](03-check-disagrees-with-opensysml-cli.md) during triage.

## Why

The viewer runs `sysml-grpc` v0.10.0, the release matching its pinned `opensysml = "0.10.0"` client. OpenSysML 0.11.0 is out (crate on crates.io; `sysml` CLI v0.11.0 installed on the dev machine). 0.11 adds checks 0.10 lacks, such as `subject-parameter-position`, so today the viewer accepts Models that OpenSysML's own CLI rejects. bike-radar-model's `check.sh` runs both, and the two disagree on its slice 1.

## Agent Brief

**Category:** enhancement
**Summary:** Move the viewer to the `opensysml` 0.11 client and the `sysml-grpc` v0.11 service it downloads.

**Current behavior:**
`viewer-opensysml` depends on `opensysml = "0.10.0"` (locked at 0.10.0). The client downloads `sysml-grpc` v0.10.0 into `~/.opensysml/bin` on first use. Models that 0.11 rejects load in the viewer without a diagnostic.

**Desired behavior:**
The viewer builds against the 0.11 client and, without overrides, runs `sysml-grpc` v0.11. Everything the viewer does today still works. Where 0.11 changes what the service returns (symbol tree, JSON element form, check answers, diagnostics), the backend adapts, and the change is recorded in `docs/opensysml-encoding.md`, using its probe to find the new shape. New service diagnostics reach the user the same way existing ones do.

**Key interfaces:**
- The `opensysml` dependency of `viewer-opensysml`, and `Cargo.lock`.
- The OpenSysML backend's readers of the service's answers (the `collect` path, the API JSON reader, expressions, checks, design values). Change them only where a contract test shows 0.11 differs.
- `docs/opensysml-encoding.md`: any new quirk or changed encoding.
- `docs/upstream/repro/`: if a repro there is fixed by 0.11, say so in the related note or memory, and don't delete the repro.

**Acceptance criteria:**
- [ ] `opensysml` is 0.11.x in `Cargo.toml` and `Cargo.lock`, and a fresh `~/.opensysml/bin` gets `sysml-grpc` v0.11.x.
- [ ] `cargo test --workspace` passes, contract and golden-file tests included. Any golden SVG that changes does so for a reason stated in the commit.
- [ ] Loading bike-radar-model at commit `59df5e2` (`requirements.sysml`, `stakeholder` before `subject` in `riderNeeds`) reports the subject-position problem as a diagnostic, as `sysml -validate` v0.11 does.
- [ ] `examples/mass-rollup` and `examples/feather-budget` give the same `check` results as before.

**Out of scope:**
- Showing the backend version: [03](03-check-disagrees-with-opensysml-cli.md).
- Using new 0.11 features beyond what the upgrade requires.
- Changing the download or override mechanism (`--sysml-binary`, `OPENSYSML_GRPC_BINARY`).
