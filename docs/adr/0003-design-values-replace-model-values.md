# Design Values replace Model Values in checks

When a Tool Link gives a feature a Design Value, every check (Satisfaction Status, Constraint Results, Computed Values, Analysis Results) uses it in place of the Model Value, by editing the Model in memory and re-parsing it, never on disk. The Model Value is kept and shown beside it; the difference is shown, not judged, and if no Design Value can be had the dependent checks are Undecided rather than falling back to the Model Value. This follows a two-step methodology: Model Values carry estimates and budgets until the design exists, and adding a Tool Link says the design now decides. We considered keeping Model Values in the checks and making a mismatch its own Verdict, but then requirements are judged against stale numbers until someone edits the `.sysml` by hand, and a tolerance would duplicate what constraints already say; we also considered requiring linked features to carry no value, but that leaves nothing to check before the design exists.
