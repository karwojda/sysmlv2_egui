# Tool Links are metadata from a library copied into the Model

A Tool Link is written as two metadata defs from our own `EngineeringTools` library package: `@ToolLink { tool; file; object; }` on the linked usage, and `@ToolProperty { name; }` on each of its features that takes a Design Value. Users copy the library's `.sysml` file into their Model; this tool ships it and recognises the defs by qualified name, but never writes it (ADR 0002). We considered reusing the standard library's `AnalysisTooling::ToolExecution`/`ToolVariable`, whose shape we follow, but `ToolExecution` says an action is carried out by a tool, not that a part is designed in one. We considered injecting the library at parse time so the Model needs no extra file, but then every other SysML tool fails to resolve `@ToolLink`. We considered one metadata per element with a mapping list of feature names, but those would be strings the parser can't check, broken silently by a rename.
